# 开源与发布检查清单

这份清单给准备公开仓库或发布新版的人使用。只想安装阅读器，请直接看[安装教程](INSTALL.md)和[使用指南](USAGE.md)，不需要完成这里的检查。

## 目前已经完成

- [x] 提供 [MIT 许可证](../../LICENSE)，以及[第三方组件说明](../../THIRD_PARTY_NOTICES.md)。字体、词库等组件保留自己的许可。
- [x] 安装包和源码包都带上许可文件，打包时排除私人阅读数据、订阅列表、日志和原始设备报告。
- [x] 提供应用安装、首次阅读、备份、升级和卸载步骤；组件检查与补装说明放在按故障现象查阅的[启动问题排查](TROUBLESHOOTING.md)，安装入口区分[正式版最新版](https://github.com/frevia/kindle-rss-reader/releases/latest)与 [beta.4](https://github.com/frevia/kindle-rss-reader/releases/tag/v0.0.4-beta.4)。
- [x] 提供[问题反馈方式](../../CONTRIBUTING.md)和[私下安全反馈邮箱](../../SECURITY.md)。
- [x] 将现有分支和标签历史中的作者、提交者邮箱，以及后续提交邮箱统一为维护者指定的地址。
- [x] 提交并推送许可证与发布配置，由 GitHub 自动编译和发布安装包。
- [x] 已发布版本的测试通过，发布附件重新下载后的校验也通过。具体代码与每次运行结果见[发布记录](https://github.com/frevia/kindle-rss-reader/releases)和[自动构建记录](https://github.com/frevia/kindle-rss-reader/actions/workflows/release.yml)。

兼容及新增功能已随 v0.0.4 beta 发布，正式版仍为 v0.0.3；公开 beta 不代表完成真机验收。以上为已有工作记录，仓库可见性由维护者单独管理。

## 公开仓库前还要确认

- [ ] **有权公开这些内容。** 确认代码、封面和测试图片可以由维护者授权使用；其他人提供的内容要保留相应说明。
- [ ] **没有不想公开的信息。** 再检查代码、文档、图片和提交历史里的地址、口令、邮箱及个人文件路径。旧提交的邮箱已处理，但开发机路径是否适合公开还需维护者确认。本地备份、旧克隆和外部缓存可能仍保留旧记录。
- [ ] **用发布附件走一次首次安装。** 从已越狱并能打开 KUAL 的设备开始，按安装教程完成复制、添加订阅、下载、离线阅读、退出和保留数据升级。未经验证的步骤应在下载页面说明。
- [ ] **准确说明支持范围。** 当前只验证过 KPW3；电脑上编译和测试通过，不等于其他 Kindle 可以使用，也不能替代长期耗电和反复休眠、退出的验证。

## 每次发布新版

1. 更新 CMake 基础版本与 beta 后缀、KUAL 版本号、对应版本发布说明和[更新记录](../../CHANGELOG.md)，将已发布功能移入对应版本。安装与使用教程清楚区分正式版、beta 和尚未发布的源码功能，分别提供下载入口。
2. 确认 GitHub 自动构建和测试通过，发布的文件来自对应版本的代码；工作流上传 Release 草稿，不会自动公开，详见[发布步骤](DEVELOPMENT.md#发布步骤)。
3. 核对 Kindle 安装包、项目源码、第三方对应源码和 `SHA256SUMS.txt` 四个附件，确认许可齐全，包内没有数据库、翻译配置／API Key、升级回滚数据或原始设备报告。
4. 核对安装包 `UPDATE.json` 的版本、`model: Kindle` 及逐文件清单；正式安装附件使用 `-Kindle.zip`，不能让兼容版在线回退到旧 KPW3 专用包。
5. 用实际准备发布的附件做首次安装、保留数据升级与恢复验证，覆盖翻译缓存、自动同步设置和已有首页适配；同时检查正式版不接收 beta、beta 可发现后续 beta 与正式版。尚未验证的设备和断电恢复范围如实写进下载页面，再手动公开草稿，beta 保留预发布标记。
6. 升级会影响用户数据或配置时，写清备份和迁移步骤，包括旧翻译变量更名及历史专用包首次 USB 迁移。

## 仍需继续完善

- 请第一次使用的读者按教程安装，收集不清楚或容易点错的步骤。
- 添加没有私人订阅内容的界面截图和示例订阅列表。
- 持续检查所用组件公布的安全问题，必要时更新。
- 完成长期阅读耗电、反复休眠、退出和 USB 连接测试，再考虑扩大支持机型。

## 检查的边界

现有检查包括本地文件、提交历史中的常见敏感内容，以及构建和安装包校验。还没有做完整安全审计，也没有重新验证每一种越狱环境。文件校验通过只能说明下载内容一致，不能证明不存在漏洞。

更细的设备与测试历史保留在[设备验证记录](DEVICE.md)中。记录中的日期、固件和版本描述当时的情况，不应当作安装教程里的操作步骤。
