# Kindle 机型兼容

兼容代码已随 **v0.0.4 beta** 发布，[beta.4 安装包](https://github.com/frevia/kindle-rss-reader/releases/tag/v0.0.4-beta.4)可直接用于普通兼容试装，无需自行构建。兼容版使用同一份静态 ARMv7 程序，按设备实际能力检查屏幕、输入和系统会话。已有设备验证记录来自 KPW3／5.16.2.1.1；本轮改变了刷新路径，仍需重新实机验收。其他机型的纯函数、事件回放和会话模拟通过不等于真机支持认证。

## 哪些设备可以参与测试

| 设备或功能 | 当前状态 |
| --- | --- |
| KPW3／5.16.2.1.1 | 有历史真机记录；最新兼容版已有首屏及进程恢复自检记录，物理触摸、翻页、长按及休眠唤醒仍需复测。 |
| 其他 ARMv7 Kindle 触摸机型 | 可以在满足下方条件后参与兼容测试，尚不能视为已支持；同一机型不同固件、面板也需分别反馈。 |
| ARMv5／ARMv6 老设备、无触摸设备、SysV 系统 | 不在当前版本范围内，不要绕过预检安装运行。 |
| 原生首页 RSS 卡片 | 仍仅限已核对文件哈希的 KPW3／5.16.2.1.1；其他机型测试普通阅读器，不启用首页 RSS。 |
| Voyage 压感键、Oasis 特殊按键、Scribe 手写笔、运行中自动旋转 | 尚未接入，不作为普通触摸阅读通过的条件。 |

测试设备需已越狱、能打开 KUAL 或书库脚本入口，使用可识别的 Kindle 5／Upstart 系统；屏幕需为受支持的 8 位灰度竖屏，并有唯一可识别的触摸屏和可用的 FBInk。**机型名称出现在识别表中，只表示程序能识别设备代码，不表示能通过屏幕、刷新和系统检查。** Colorsoft、Scribe 或其他高分辨率设备也遵循这些条件，不能仅凭名称或分辨率判断可用。

详细技术条件见[当前条件](#当前条件)。不清楚自己的设备是否符合时，可先按下面步骤导出只读诊断，请维护者确认。

## 测试安装流程

### 1. 备份并确认安装包

正常退出已有阅读器，连接电脑，备份整个 `native-rss` 文件夹；首次安装也请备份重要书籍和文件。已有首页适配时先按[首页说明](HOME.md#启用停用和卸载)停用，测试期间保持系统正常竖屏并关闭设备密码锁。

普通兼容试装下载 [beta.4](https://github.com/frevia/kindle-rss-reader/releases/tag/v0.0.4-beta.4) 中的 **`RSS-Reader-v0.0.4-beta.4-Kindle.zip`**，旧 beta 推荐直接 USB 升级。需要从 beta.3 在线升级时，须先[修复旧启动器](INSTALL.md#旧版升级前修复启动器)并重新打开阅读器，再按[在线升级测试](INSTALL.md#在线升级测试)操作。记录完整文件名和下载来源；自行构建的 `kindle-rss-kindle-dev.zip` 还需记录提交号。

注意：[正式版最新版入口](https://github.com/frevia/kindle-rss-reader/releases/latest)仍为 v0.0.3，不包含上述 beta。只使用本项目的 `-Kindle.zip` 兼容包；历史 `-KPW3.zip` 改名也不会获得兼容能力。

### 2. 复制文件，先导出诊断

按[安装教程](INSTALL.md#安装)将 `native-rss`、`documents`、`extensions` 合并复制到 Kindle 根目录，保留 `native-rss/data` 及其他应用文件。安全弹出并拔线后，先不打开 RSS Reader，执行以下任一入口：

- 书库 → **RSS设备诊断**。
- **KUAL → Kindle RSS → 导出 RSS 诊断报告**。

诊断只读取设备信息并写入报告，不接管屏幕、不抓取触摸、不暂停系统进程，也不修改固件。完成后连接电脑，复制 `documents/RSS-device-report.txt`，另存为试装前报告；再次导出会覆盖同名文件。诊断入口找不到时，先按[启动问题排查](TROUBLESHOOTING.md)检查入口。

报告中的 `layout=accepted`、`input=accepted` 分别表示屏幕布局和触摸设备通过静态检查；`rejected`、`unsupported`、探测失败或缺少必要工具时，先反馈报告，请维护者判断。即使 `probe_exit=0` 或某个 `fbink_probe_exit=0`，也不代表所有条件通过；`current_build_hardware_verified=0` 是程序的验证状态标记，不是本机测试结果。看不懂报告时不必自行修改设置或系统文件。

### 3. 首次启动

确认诊断没有拒绝项、疑问已澄清后，安全弹出并拔线，使用 **KUAL → Kindle RSS → RSS Reader** 或书库 **RSS Reader** 启动。启动器还会检查刷新工具与系统会话，诊断通过不保证一定能启动。

首次进入应看到完整列表或无订阅的空页面，系统状态栏不应叠在正文上，画面不应持续闪烁。点开即退出、画面错位或触摸方向错误时，停止后续测试，记录现象。不要通过跳过预检、替换共享工具或修改固件强行启动。

### 4. 逐项检查基础阅读

每项记录“正常／异常／未测试”，不要把未操作的项目当作通过；遇到影响退出或数据的异常先停止。

| 项目 | 操作和观察内容 |
| --- | --- |
| 显示与触摸 | 检查四边文字和按钮有无裁切、异常留白、比例错误；依次点击位于不同边角的菜单、返回、翻页、收藏等按钮，确认命中位置与画面一致。 |
| 键盘 | 在订阅编辑或搜索中输入英文、拼音并选择中文候选，检查边缘按键、删除和返回；无需提交私人地址。 |
| 同步与图片 | 添加一份公开 RSS／Atom 订阅，手动同步并打开有图文章；记录同步、正文和图片是否正常。同步结束后断开 Wi-Fi，确认缓存仍可阅读。 |
| 翻页与排版 | 分别用轻点和左右滑动往返翻页至少 10 次，观察漏触、错页、残影及卡顿；调整字号，并分别检查新版和原排版。 |
| 选词 | 长按约 0.6 秒选词、跨几行拖选、调整两端，检查选区是否跟手、松手是否误翻页；不必配置翻译服务即可测试选区。实际翻译需自备 Key，未测试可注明。 |
| 位置保存 | 在文章中段返回列表，重新打开，确认阅读位置；收藏一篇文章，退出重开后确认收藏还在。 |
| 正常退出 | 从文章列表 **菜单 → 退出**，确认系统首页或书库恢复，触摸和系统状态栏正常；再次打开阅读器。 |
| 休眠唤醒 | 阅读时用电源键进入休眠，再唤醒；阅读器休眠时会退出，检查系统界面恢复，并重新打开确认位置。 |
| USB 传文件 | 先正常退出阅读器，再连接电脑，确认 Kindle 磁盘能出现、文件可读取；仅检查充电图标不算通过。USBNetwork 用户先确认处于 USBMS 模式。 |

基础测试不要求强杀进程、模拟断电、在线安装更新或测试阅读中插 USB；这些需要维护者另行指导。自动同步、网页正文和实际翻译可作为额外项目记录，未测试不影响本次反馈提交。

### 5. 保存结果与结束测试

无论成功或失败，都先正常退出阅读器，再导出一次诊断并复制到电脑，与试装前报告分开保存。报告包含最近会话日志；如同一次测试出现多种异常，优先在首次异常后留存报告，避免后续运行覆盖线索。无法正常退出时记录卡在哪个画面、故障时间及设备是否仍响应，停止反复重试，通过下方渠道联系维护者。

不继续使用时，按[卸载步骤](INSTALL.md#卸载)仅移除本应用；需要回退时，先另存当前数据，再恢复试装前的整套应用备份。恢复旧 `data` 会丢失测试期间新增的订阅、收藏和阅读进度，不要把它覆盖到唯一一份新数据上。不要删除共享启动工具、其他书籍或系统文件。

## 当前条件

| 项目 | 条件与行为 |
| --- | --- |
| 程序 | ARM32／ARMv7、静态 EABI5 soft-float；不加载设备的 glibc，不按系统动态链接器复制两套应用。ARMv5／ARMv6 老设备不在范围内。 |
| 屏幕 | 8 位灰度、竖屏，宽 600–2560、高 800–3400；校验 stride、偏移、虚拟高度和实际映射内存。其他位深拒绝启动，不修改系统屏幕模式。 |
| 界面 | 保留 1072×1448 逻辑排版，等比缩放并居中留白；输入反向映射至同一画面。KPW3 尺寸不缩放，其他设备的分页与逻辑字号保持一致。 |
| 刷新 | 依次检查设备已有的 `/mnt/us/libkh/bin/fbink`、`/usr/bin/fbink`、`/mnt/us/koreader/fbink`，选择机型识别、尺寸与 stride 一致的程序；拒绝 sunxi 和反色 framebuffer。预检、阅读刷新和退出恢复使用同一程序，不替换共享工具。按变化区域刷新，每六次有效更新全刷；同时检查退出码与有界诊断输出，等待错误或未知诊断会退出设备循环，不提交成功帧。 |
| 触摸 | 根据 evdev 能力发现触摸屏，支持 MT Type B、MT Type A、已知 Basic 2019 面板的 Snow 协议和单点 ABS／BTN_TOUCH；Type B 以首个活动槽为主触点，逐槽保留坐标，支持非零槽、多指取消、长按、移动及事件丢失保护。KPW3 的旧版 `cyttsp4_mt` 缺少 `INPUT_PROP_DIRECT` 且声明 `BTN_TOOL_FINGER`，按精确驱动名允许检测，仍要求触摸按钮和有效坐标轴，并排除 pointer／pen。多个不明确候选会拒绝启动。 |
| 系统会话 | 需要 Upstart、可解析的 Kindle 5 固件版本、可验证身份的 awesome／volumd 和 LIPC 电源／浮层接口；Juno 状态栏存在时一并接管。发现 `statusbar.conf` 时查询独立状态栏，将运行进程纳入同一暂停／恢复流程；未知状态拒绝启动。未满足条件时保持拒绝，不绕过 USB 数据保护。 |
| 电量 | 优先通过 LIPC 读取 powerd 的 `battLevel`／`isCharging`，查询失败或数据无效时逐项回退 sysfs；没有有效电量时显示未知。 |

尺寸回归覆盖 600×800、758×1024、1072×1448、1236×1648、1264×1680、1404×1872 和 1860×2480。分辨率相同不代表驱动、触摸方向、电源与固件相同，不能据此生成已支持机型白名单。

本轮不启用运行中的自动旋转、Voyage 压感翻页键、Oasis 特殊按键或 Scribe 手写笔。请在系统正常竖屏姿态启动；屏幕布局运行中改变会停止设备绘制，恢复时不把旧快照写入新布局。触摸轴向仍需各机型实际校准。

## 面板与固件差异

Basic 2019 的部分面板使用带 tracking ID、没有标准 MT slot 的 Snow 协议。识别到该机型后才启用例外，保留坐标增量和重复 ID，不把每个报告都当成新按下；全局抬手清空接触，多指持续取消至全部释放。同机型存在标准面板修订，有 MT slot 时优先 Type B，Snow 收到标准释放事件时回退。识别仅在本机有界读取设备代码，不写入完整序列号；未知机型不会自动套用该例外。

新固件的独立状态栏可能绕过 Pillow 与 awesome 继续绘图。启动器从 Upstart 查询其 PID，并核对进程名和启动时间，暂停该进程的全部线程；退出和启动器强杀恢复均遵循相同身份检查，不向已替换进程发送信号。原本未运行的状态栏不会被启动；阅读期间发现状态栏启动、重启或身份变化，会退出阅读并恢复系统。此处不停止／重启系统任务，也不修改固件或服务配置。

启动器按 `/etc/prettyversion.txt` 选择成对的 Pillow 操作：Kindle 5.6.5 之前使用 `interrogatePillow` 的 `hideMe()`／`showMe()`，5.6.5 起使用 `disableEnablePillow disable`／`enable`；正常退出、启动失败和强杀监护恢复使用同一策略。缺少版本、格式异常、重复版本或非 Kindle 5／SysV 系统在界面接管前拒绝启动。SysV 老设备的无触摸界面、旧 CPU 和显示模式不在现有 ARMv7 触摸版范围，不能仅跳过 Pillow 检查就宣布支持。

外部 LIPC／FBInk 命令由独立进程监护：监护拥有命令进程组、截止时间和阅读器生命周期管道。阅读器被强杀或消失时，监护终止命令及其同组后代；命令正常结束时也清理剩余后代。会话 FIFO 仍由真正运行的工具持有，系统恢复继续等待其实际关闭，避免孤立工具无限占用 FIFO，或在工具尚未退出时恢复界面与 USB。fork 后的监护仅使用预先准备的数据和异步信号安全的系统调用，不访问阅读器线程里的数据库、分配器或锁。

官方 FBInk CLI 的 `--refresh -w` 分支可能在等待失败时仍退出 0，所以刷新适配器同时检查最多 4096 字节的标准输出／错误输出。在 `-q` 模式下，仅允许没有诊断，或单条已知的“不支持可选提交等待”警告；后者不影响随后的完成等待。其他输出（包括完成等待失败、额外或未知警告）、输出超限、非零退出及超时都按失败处理。此策略依赖官方 FBInk 的错误诊断契约；定制版本或诊断格式变化会保守退出，不能静默忽略。对应上游实现见 [CLI 刷新等待](https://github.com/NiLuJe/FBInk/blob/master/fbink_cmd.c#L2534-L2545) 与 [WARN 诊断](https://github.com/NiLuJe/FBInk/blob/master/fbink_internal.h#L434-L445)。

## 机型配置与电量回退

`kindle_profile()` 保存 Touch、Paperwhite 1–6、Basic 2014–2024、Voyage、Oasis 1–3、Scribe 与 Colorsoft 系列的已知设备代码、DPI、显示平台提示及 Snow 例外。标准 evdev 能力优先于机型协议例外。DPI 仅用于诊断，当前仍采用统一逻辑画布；`classic`／`zelda`／`rex`／`mtk` 是平台提示，不是本项目已经验证的后端列表。

诊断新增 `model`、`display_dpi`、`display_platform_hint`、`touch_policy`、`historical_firmware`。只有 Paperwhite 3 记录历史固件 5.16.2.1.1；历史证据不代表本轮程序的真机验收，所以本轮明确输出 `current_build_hardware_verified=0`。未知或无效设备代码返回 `Unknown`、DPI 0，不启用 Snow；仍执行完整能力检查。完整序列号不会出现在报告中。

电量每 30 秒随原有状态采样一次。LIPC 查询使用固定程序与参数，不经过 shell；容量只接受 0–100，充电只接受 0／1。每项最多 200 ms、32 字节，两项分别回退到 sysfs，不因一项成功丢失另一项的回退值。诊断同时列出原始 powerd 查询与电源节点，便于区分服务不可用和节点差异。

## 刷新性能测量

退出设备会话时，日志新增一行 `display_metrics`：`frames` 是提交次数，`skipped` 是无像素变化的次数，`refreshes` 是成功刷新次数，`scale_us`／`diff_us`／`copy_us`／`fbink_us` 分别累计缩放、差分、复制、外部 FBInk 调用及等待的微秒数。只汇总数字，不记录正文。诊断报告末尾的会话日志可直接保留这行；被 SIGKILL 的阅读器无法输出自身汇总。

同一机型上分别测试列表、正文翻页、键盘和长按选词，记录会话时长、操作次数、上述耗时以及残影。用 `scale_us / frames` 衡量缩放成本，用 `fbink_us / refreshes` 衡量外部刷新成本（分母为零时不计算）；后者包含内核刷新等待，不能全部归因于 CLI 启动。原生 DPI 排版会改变分页、键盘和触摸布局，常驻 FBInk 会引入进程及恢复生命周期；在取得实机性能数据前保留现有路径，不以主机跑分替代这些判断。

## 第一次检查新设备

按前面的[测试安装流程](#测试安装流程)进行，并使用[兼容反馈模板](#怎么反馈兼容情况)提交结果。只读诊断与基础测试不要求 SSH；强杀恢复、断电和升级恢复另行安排，不作为普通用户首次试装步骤。

## 首页卡片与在线升级

原生首页 RSS 卡片是独立的固件功能，仍只接受已核对哈希的 KPW3／5.16.2.1.1。普通阅读器的兼容范围不会放宽首页文件校验，见 [HOME.md](HOME.md)。

新安装包使用 `UPDATE.json` 的 `model: Kindle` 和 `-Kindle.zip` 附件名。兼容版拒绝旧 KPW3 包，防止其他设备在线安装回不兼容的程序；历史专用开发版先通过 USB 升级一次。个人数据库结构不因本次适配改变。

## 实现参考

刷新参数遵循 [FBInk CLI](https://github.com/NiLuJe/FBInk/blob/master/CLI.md)，输入协议遵循 [Linux 多点触摸协议](https://docs.kernel.org/input/multi-touch-protocol.html)，电源节点对照 [KOReader Kindle 设备实现](https://github.com/koreader/koreader/blob/3d40440e7f07a156dfee6cffc50400654d2336da/frontend/device/kindle/device.lua)。各项目的硬件支持范围不等于本项目的实机验收范围。

电源属性与固件分界对照同一固定版本的 [KOReader powerd](https://github.com/koreader/koreader/blob/3d40440e7f07a156dfee6cffc50400654d2336da/frontend/device/kindle/powerd.lua) 和 [Kindle 启动脚本](https://github.com/koreader/koreader/blob/3d40440e7f07a156dfee6cffc50400654d2336da/platform/kindle/koreader.sh)。
