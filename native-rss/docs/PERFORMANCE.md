# RSS 性能排查（2026-10-23）

这份文档记录某次速度排查的过程和结果，供开发时回查。普通安装和使用请看[安装教程](INSTALL.md)与[使用指南](USAGE.md)，无需执行下面的测试命令。

本轮针对左上角导航、全部文章切换及其他常用交互进行代码排查和桌面基准。**优化版已安装到 Kindle，程序及资源校验通过，设备只读检查正常，订阅和阅读数据保持不变；交互延迟尚未实机计时。不能将桌面耗时当作设备响应时间，也不能据此断言实机卡顿已完全消除。**

## 已处理

- `App::reload` 原先为所有文章标题排版后才显示首屏。现在按访问的页计算边界，保持文章顺序、动态行高、阅读状态和前后翻页行为。刷新仍保留原页码，列表缩短时自动回到有效页。总页数未发现前显示 `当前页 / …`，到最后一页后显示精确页数；顶部文章总数仍准确。
- `Canvas::icon` 原先对每个像素、每条线段重复计算距离和开方。现在预计算线段参数，比较平方距离，每像素仅开方一次。固定基准覆盖 18 个图标、6 个尺寸和深浅底色，允许跨平台 1 级灰度舍入误差。主线程复查额外发现并修复极窄矩形图标区域的距离上限问题，已用先失败后通过的测试覆盖。
- `changed_region` 原先逐个扫描约 155 万像素。现在先按行比较，仅查找变化行的左右边界，保留原有 8 像素对齐与刷新区域。稀疏、同一行多点、四角、全屏和无变化场景都有测试。没有修改墨水屏波形、刷新频率和等待机制。

## 桌面对照

Apple Silicon macOS，CMake Release，1072×1448，随开发包提供的 `vendor/runtime/reader.ttf`。内存 SQLite，1 万篇合成文章，混合长短标题；长文包含 1000 段文字，图片为 944×1000 灰度缓存。旧版与新版交替运行 5 次，表中为每次输出的操作均值的中位数，单位毫秒。单次冷启动受字体和系统缓存影响较大，不作为主要结论。

| 操作 | 优化前 | 优化后 |
|---|---:|---:|
| 全部文章切换和绘制 | 17.862 | 4.629 |
| 首次打开导航（字体缓存已部分预热） | 2.647 | 1.652 |
| 导航重复绘制 | 1.784 | 0.720 |
| 列表下一页 | 1.179 | 0.691 |
| 分组切换 | 20.567 | 7.036 |
| 标题搜索 | 21.115 | 7.509 |
| 长文打开和排版 | 3.270 | 2.962 |
| 正文下一页 | 0.758 | 0.540 |
| 阅读设置 | 1.365 | 1.103 |
| 图片重绘 | 1.390 | 1.379 |
| 返回列表 | 1.387 | 0.784 |

局部屏幕变化检测另测：约 2.3 ms → 0.07 ms。数据库元数据查询仍约 3.7 ms；本轮未修改 SQL。截图逐像素比较：导航、正文、阅读设置完全一致；列表仅页数显示区域变化。

这些基准不包含设备触摸采样、LIPC 命令、e-ink ioctl 等待、磁盘延迟和网络。不能按上述倍数推算 Kindle 的体感收益。

## 其他链路排查与剩余边界

- 同步请求已在工作线程执行，未发现点击导航会同步联网。进度通知可能触发页面重绘，图标优化会降低其 CPU 成本。
- SQLite 仍使用默认日志模式和 5 秒 busy timeout；后台批量写入可能与 UI 读写竞争。内存基准没有复现真实闪存上的锁等待，本轮未改变数据库持久化和 USB 恢复约定。
- 列表仍一次读取全部元数据，量级继续增长时查询和内存占用仍会增加；只消除了全量标题排版。很深页码的手动刷新需要重新计算之前的页边界。
- 正文打开会完整排版；翻页复用排版结果。1000 段文字的基准没有显示与列表切换相当的开销，超长文章仍需按实际数据复测。
- 图片只读取当前显示图片的缓存；打开设置或重新绘制时可能重新读取图片。合成图片重绘未见显著回归，闪存 I/O 未测。
- 拼音候选已有二分查找；本轮运行既有拼音及输入交互测试。
- 设备循环会同步等待墨水屏刷新；触摸时每隔至少 5 秒执行一次有 2 秒超时的 LIPC 命令。二者可能造成设备特有延迟，需要实机分段计时后再改，未绕过恢复与电源保护。

## 复测

```sh
rtk proxy cmake -S native-rss -B native-rss/build-perf -DCMAKE_BUILD_TYPE=Release
rtk proxy cmake --build native-rss/build-perf -j 6
rtk proxy ctest --test-dir native-rss/build-perf --output-on-failure
rtk proxy native-rss/build-perf/rss-performance native-rss/vendor/runtime/reader.ttf 10000
```

`rss-performance` 仅写内存数据库，不使用个人订阅、不联网。可选 `RSS_BENCH_SNAPSHOTS` 指定目录保存列表、导航、正文和设置 PGM。另可用 1000、100000 篇检查增长趋势。计时不设硬阈值，避免机器负载导致不稳定测试；文章顺序、分页和刷新区域由功能测试校验。

实际设备验收建议在不同文章量下重复：左上角展开/关闭、全部文章/分组/搜索切换、连续前后翻页、同步中操作、长文与图片阅读，分别记录 tap、draw、present/LIPC 耗时。
