# 启动问题排查

遇到功能入口、翻译、同步、启动、存储或首页显示问题时，可以按下面的现象排查。正常安装和使用见[安装教程](INSTALL.md)与[使用指南](USAGE.md)。

## 找不到自动同步、翻译或在线升级

这些功能已随 v0.0.4 beta 发布，正式版 v0.0.3 尚不包含。请在 [beta.4 页面](https://github.com/frevia/kindle-rss-reader/releases/tag/v0.0.4-beta.4)下载 `RSS-Reader-v0.0.4-beta.4-Kindle.zip`，按[安装教程](INSTALL.md)通过 USB 安装并保留个人数据。`/releases/latest` 仍指向正式版，不会跳到 beta。

支持在线升级的正式版只检查更高正式版本，beta 会检查后续 beta 和正式版；都不会安装草稿、主分支提交或同版本开发包。beta.1～beta.3 建议直接 USB 安装 beta.4，或先修复启动器再在线升级，见[安装说明](INSTALL.md#旧版升级前修复启动器)。

## 升级后显示“上次升级未完成”

若完整提示为“上次升级未完成，已恢复升级前的程序与阅读数据”，表示回滚已执行，需先在设置确认当前版本。beta.1～beta.3 存在已确认的锁交接故障：安装成功后，新启动器仍可能因旧 timeout 监控进程持锁而提示“阅读器已经运行”，随后回滚；beta.4 的启动器已修复。

正常退出并备份整个 `native-rss`，按[旧版迁移说明](INSTALL.md#旧版升级前修复启动器)通过 USB 升级到 beta.4，或先修复旧启动器再重开测试。不要删除 `.update`、数据库或 SQLite 日志来跳过保护。若修复后仍失败，立即[导出诊断](INSTALL.md#日志反馈)，并记录升级前后版本与失败阶段；休眠、系统进程变化和网络超时仍须分别排查。

## 自动同步没有立即开始

先在 **菜单 → 设置 → 自动同步订阅** 确认已开启，再连上 Wi-Fi，返回文章列表。应用根据最近的同步记录和尝试时间按 30 分钟节流；刚同步、失败或取消后不会立即再试。设置、输入、确认操作以及其他后台任务进行时会推迟，设备休眠时不会唤醒。

需要立即下载时用 **菜单 → 同步**；这个入口也可查看正在进行的任务和失败项目。首页 RSS 卡片只显示本地缓存，本身不会同步订阅或触发翻译。

## 翻译提示配置错误、失败或仍显示旧译文

先按[配置翻译服务](USAGE.md#配置翻译服务)检查 `native-rss/data/translation.conf`，确认文件没有额外的 `.txt` 后缀，并使用当前 `RSS_TRANSLATION_*` 变量名。旧变量行、`export` 或带引号的值都需要按示例修改；开发环境中的同名环境变量优先，空值也会覆盖文件。

鉴权失败时核对服务商及其 API Key、模型权限、完整 endpoint；切换服务后删除或更新原先的模型与地址覆盖项。限流、余额不足或网络错误处理后需手动重试，应用不会自动重试可能已计费的请求。同步或其他翻译任务进行时，先等它完成或取消。

切换服务不会自动重译或清空缓存，继续未完成文章也可能复用旧服务的段落。正文或翻译格式变化后提示需重新翻译时，手动发起翻译即可，已保存原文和阅读数据会保留。反馈时只提供提示文字和服务商、模型名称，不要上传 API Key 或完整配置文件。

## USB 只能充电，电脑不显示 Kindle 磁盘

先从文章列表的 **菜单 → 退出 → 退出应用** 正常退出，再拔插数据线。阅读器运行期间会暂时禁止 USB 磁盘导出，退出后恢复。

已退出仍不能传文件，且安装了 USBNetwork 时，检查 **KUAL → USBNetwork → USBNetwork Status**：USBNet 是 USB 网卡模式，USBMS 才是文件传输模式。可用 **Toggle USBNetwork** 切回 USBMS，再拔插数据线，无需重启整机。只需要 Wi-Fi 调试时，再选择 **Restrict SSH to WiFi, stay in USBMS**；它让后续启用 SSH 时保留 USB 文件传输模式，不会立即切换当前模式。

仍无磁盘时，换能传数据的线和电脑 USB 接口；若问题可重复出现，保留现场和退出日志，继续检查系统 USB 服务。不要删除数据库或重装阅读器来尝试恢复 USB。

## 打开文章提示 database or disk is full

这表示数据库写入遇到了空间或容量限制，不应通过删除数据库解决。先返回文章列表并正常退出，连接电脑备份 `native-rss`；将确认不再需要的个人文件移到电脑，或在应用的 **菜单 → 同步 → 缓存管理** 中清理已读内容。不要手动删除 `rss.sqlite` 或其日志文件来腾空间。

v0.0.3 开发版已修复错误页与正文之间的返回死循环：打开失败时回滚已读及进度变更，返回时保存失败也能离开正文，但此次进度可能无法保存。释放空间后再尝试。若可用空间充足仍报错，请按[日志反馈步骤](INSTALL.md#日志反馈)提供信息，避免反复重装或覆盖阅读数据。

## 原生首页没有 RSS 订阅卡片

先确认已单独安装[首页适配](HOME.md)，并在阅读器 **菜单 → 设置** 中开启“在 Kindle 首页显示 RSS订阅”。普通阅读器安装不包含设备固件补丁；原生首页也必须使用带对应推荐卡位的视图。

已安装适配时，正常退出阅读器并返回 Kindle 首页等待刷新。旧版适配升级后需再执行一次“启用首页 RSS”补装恢复任务；仍无显示时查看[首页适配的状态与恢复说明](HOME.md#启用停用和卸载)。不要删除系统首页文件或个人数据库。

## KUAL 里没有阅读器

连接电脑，检查 Kindle 的 `extensions` → `native-rss` 中是否有 `menu.json`。如果没有，从安装包补复制 `extensions` 文件夹的内容。安全弹出并拔线，重新打开 KUAL，查看 **Kindle RSS → RSS Reader**。

## 点开后马上退出

1. 在 Kindle 设置中关闭设备密码锁。使用兼容版时先核对[机型兼容条件](COMPATIBILITY.md)；历史 KPW3 专用包不能用于其他机型。
2. 对照[安装教程中的目录图](INSTALL.md#文件要放成这样)，确认文件位置正确，没有多套一层解压文件夹。
3. 检查下面的屏幕恢复工具；已经具备时，不要重复安装补丁，按[安装教程中的日志反馈步骤](INSTALL.md#日志反馈)提供检查文件。

### 检查屏幕恢复工具

兼容版使用 FBInk 刷新阅读画面及恢复系统画面，安装包尚未附带它。KUAL 和书库两种入口都需要这个工具；能够打开其他第三方应用，不代表它一定已经存在。工具还需支持当前机型。启动器依次检查 `libkh/bin/fbink`、系统 `/usr/bin/fbink` 和 `koreader/fbink`，使用通过预检的程序；全部失败时在接管前退出，不替换已有共享工具。

1. 连接电脑，打开 Kindle 磁盘中的 `libkh` 文件夹，再打开 `bin`，查看里面是否有名为 **`fbink`** 的文件。
2. 文件已经存在时，先保留原文件。如果应用仍打不开，按[日志反馈步骤](INSTALL.md#日志反馈)提供检查文件，不要反复重装。
3. 如果书库里已有 **Run Hotfix**，安全弹出并拔线，点开运行，等处理完成。再连接电脑，检查 `libkh` → `bin` → `fbink` 是否已经出现。
4. 如果没有 **Run Hotfix**，或运行后仍没有这个文件，再看下方的补装步骤。

文件存在只是初步检查；是否可执行以及其他启动条件，仍需结合检查文件判断。

## 书库里没有 RSS Reader

1. 检查 Kindle 磁盘的 `documents` 中确实有 **`RSS阅读器.sh`**，并且 `native-rss` 文件夹也已完整复制。
2. 安全弹出并拔线，回到书库，把筛选切到 **全部**，不要只显示“书籍”，再等待列表刷新。
3. 如果刚装好 Hotfix，确认已经运行过书库里的 **Run Hotfix**。然后重新连接电脑，把安装包中的 `documents` 内容再复制一次，安全弹出并拔线。
4. 仍不出现时，在 Kindle 设置中选择**重新启动**，回到书库再看。这里是重启，不是恢复出厂设置。

书库入口依赖 Scriptlets / SH_Integration，它让书库能打开随包提供的 `.sh` 文件，不需要用户自己编写脚本。从 KUAL 打开不需要它，也不必同时准备两种入口。

如果其他 `.sh` 应用可以从书库打开，先核对本应用的文件位置；如果都不能，按下面的步骤检查越狱后的环境设置。已有可用的 KUAL 时，也可以尝试 **KUAL → Kindle RSS → RSS Reader**。

## 补装设备工具

**只有确认缺少 FBInk，或希望使用书库入口但缺少 Scriptlets 时，才需要补装。** Universal Hotfix 可以提供这两项工具；已经具备所需工具、阅读器能正常打开时，不必重复安装。

### 安装并运行补丁

以下步骤从“设备已越狱”开始。先退出正在运行的越狱应用，回到 Kindle 书库，并开启飞行模式，避免同时下载系统更新。

1. 在电脑上[下载 Universal Hotfix 补丁](https://github.com/KindleModding/Hotfix/releases/latest/download/Update_hotfix_universal.bin)。下载到的文件名应为 **`Update_hotfix_universal.bin`**，不要改名，也不用解压。下载链接失效时，到[补丁的最新版页面](https://github.com/KindleModding/Hotfix/releases/latest)找这个文件。
2. 连接 Kindle，把这个 `.bin` 文件复制到 Kindle 磁盘，**与 `documents` 文件夹并排放置**，不要放进 `documents` 或 `mrpackages`。
3. 如果这一层还有其他 `.bin` 安装文件，或 `update.bin.tmp.partial`，先移到电脑备份。本次只保留刚下载的 Hotfix 安装文件；不要混放其他系统更新文件。
4. 在电脑上安全弹出 Kindle，再拔掉数据线。
5. 打开 Kindle 的 **设置 → 全部设置 → 右上角三个点 → 更新 Kindle**；确认安装，等处理完成。不同界面的入口位置可能略有区别，找的是“更新 Kindle”这一项。
6. 回到书库，找到 **Run Hotfix**，点开运行。等它处理完并回到书库；**复制并安装 `.bin` 后，还要完成这一步，不能省略。**
7. 按[安装教程](INSTALL.md#安装)的步骤复制 RSS Reader 的三个文件夹，安全弹出并拔线。在书库中等待列表刷新，看到 **RSS Reader** 后点开。

这里使用“更新 Kindle”是为了安装 **Hotfix 补丁 `.bin`**；RSS Reader 安装包本身仍然只需要复制文件。无需下载 Amazon 的系统固件来安装本应用。

安装完成后，连接电脑确认 `libkh` → `bin` → `fbink` 已出现；想使用书库入口时，再确认能看到并打开 **RSS Reader**。补丁来源和安装步骤见[上游说明](https://github.com/KindleModding/kindlemodding.github.io/blob/main/content/jailbreaking/Legacy/post-jailbreak/setting-up-a-hotfix/__index.md)。

### “更新 Kindle”是灰色的，怎么办

先检查是否已拔掉 USB 数据线，以及 `Update_hotfix_universal.bin` 是否与 `documents` 并排放置。

如果之前在 KUAL 中用 **Rename OTA binaries** 关闭过更新，先保持飞行模式，打开该菜单并选择 **Restore**，再安装 Hotfix。补丁安装并运行完成后，回到同一菜单选择 **Rename**，恢复原来的更新阻止设置。没有使用过这个工具，就不要额外安装它。

仍然无法安装时，先停在这里，按上方的社区安装说明检查，或反馈设备型号和提示文字。不要通过升级系统或恢复出厂设置碰运气；已经可用的 KUAL 入口仍可继续使用。

更多启动条件和实现细节见[开发参考](DEVELOPMENT.md#维护设备启动环境)。
