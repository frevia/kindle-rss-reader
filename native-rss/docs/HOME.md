# 原生首页 RSS 卡片（可选开发功能）

启用后，原生首页上的 Kindle+ / Kindle Unlimited 推荐区域改为“RSS订阅”书架。每个启用的订阅源显示一张固定书卡，最多三张，按最新文章发布时间排序。封面沿用首页书籍的 2:3 比例，卡片顶部显示订阅名称，中部优先展示该源最新未读文章标题（没有未读时回退到最新文章），底部显示未读数。点击有文章的书卡直接打开该篇正文并按阅读器正常规则标为已读；空订阅卡和标题栏箭头进入阅读器列表。

书卡使用原生首页的字体和触摸组件，由本地数据呈现，不写入书库，也不接入商品购买或下载流程。没有文章的订阅源仍保留卡片；未添加订阅或后台版本较旧时显示一张阅读器入口卡。超过三份订阅可通过标题入口在阅读器内查看。下方重复的 Kindle+ 试用推广卡位折叠，只保留“发现好书”上方升级提示卡位中的订阅书架。其他推荐区域保留原来的行为。首页必须使用带推荐区的视图，并且系统本身已提供这张 Kindle+ 卡片；组件不会强行创建缺失的推荐区。

当前只支持已经核对原文件 SHA-256 的 KPW3 固件 5.16.2.1.1。普通安装不会自动启用；不匹配的系统文件会拒绝适配。新版固件需要单独验证后加入支持清单。

## 阅读器内的显示开关

打开 RSS Reader，点击左上角菜单 → 设置 → “在 Kindle 首页显示 RSS订阅”。已有安装默认开启，设置立即保存，退出阅读器返回 Kindle 首页后自动生效。关闭会收起整个 RSS 区域；再次开启会恢复原来的订阅书卡。订阅、文章、未读状态和阅读位置都会保留，下方重复试用推广仍然隐藏。

这个开关只控制已安装首页适配的显示。首次安装适配、完整停用或卸载仍使用下方 KUAL 入口或 `home.sh`；没有安装适配时，显示开关不会自动修改系统文件。

## 数据和刷新

RSS 阅读器仍负责添加订阅、联网同步和保存阅读记录。首页后台只读本机 `native-rss/data/rss.sqlite`，有首页连接时每两秒检查数据版本，变化后推送摘要。首页刷新本身不会下载新的 RSS 文章，也不依赖电脑或 SSH 保持连接。

断线时保留上次显示的摘要，自动重连；另有不触发界面更新或状态写盘的连接心跳，弥补该固件偶尔不通知断线的问题，静默断线通常在一分钟内重连。数据库暂时忙碌时保留已有数据并重试。阅读器占用屏幕期间，启动器暂停首页后台；正常退出或启动器意外终止后由恢复流程继续后台刷新。设备休眠和离线期间不保证两秒内更新，唤醒返回首页后重新接收本地数据。

后台仅监听本机 `127.0.0.1:12681`。协议只传摘要和确认消息；`feedCards` 提供最多三个启用订阅源的名称、未读数、未读优先的文章标题与 entryId，原有 `items` 摘要继续兼容。文章入口在应用目录内按正整数编号生成固定脚本，不进入图书馆；正文启动参数严格校验，摘要不能传入任意命令或网址。全局未读数与阅读器“全部分组 / 未读”口径一致，每张书卡显示该订阅源的未读总数。阅读器未读列表的计数使用与列表相同的数据库筛选条件，保留位置时显示的灰色已读行不计入未读。

## 为本机生成开发安装包

先完成 [开发构建](DEVELOPMENT.md)。需要从自己的设备取出原始 `/app/KPPMainApp/js/KPPMainApp.js.hbc`，并准备能生成 HBC84 的 Hermes 编译器（已使用 Hermes 0.9.0 验证）。不要对已经挂载适配副本的路径取样。

在仓库根目录运行以下命令，将路径换成本机文件位置：

```sh
rtk proxy python3 native-rss/tools/build_home_patch.py \
  --original /absolute/path/KPPMainApp.js.hbc.original \
  --hermesc /absolute/path/hermesc \
  --output-dir native-rss/output/home-adapter
rtk proxy python3 native-rss/tools/build_arm.py
rtk proxy python3 native-rss/tools/package.py --home-patch native-rss/output/home-adapter
```

生成器先校验固件哈希，再合并首页适配代码。生成目录中的 `patched.hbc` 只供本机核验，安装包只收录需要原文件才能重建的差分配方及校验清单，不包含完整 Amazon 首页文件。源码包也不包含原固件或设备数据。

不传 `--home-patch` 时仍可安装普通阅读器；首页启用入口会提示缺少本机固件补丁。修改 `home/card.js` 后必须重新生成补丁，打包程序会拒绝旧配方。

## 启用、停用和卸载

将开发安装包按 [安装教程](INSTALL.md) 合并复制到 Kindle，保留个人 `native-rss/data`。安全弹出、拔线，关闭设备密码锁，保持设备唤醒，并先退出 RSS 阅读器。

在 KUAL → Kindle RSS 中选择“启用首页 RSS”。也可以通过 SSH 执行：

```sh
sh /mnt/us/native-rss/home.sh enable
sh /mnt/us/native-rss/home.sh status
sh /mnt/us/native-rss/home.sh disable
```

启用会暂时重载系统首页；收到首页数据确认才算成功。等待约一分钟，超时或失败自动移除本组件的启动配置和挂载；另有独立恢复任务处理启用过程意外中断。未知的启动配置或挂载不会被覆盖。

启用前会检查状态分区剩余空间。系统重载产生的报告保存在 USB 盘的 native-rss-backups/home-restart-reports，避免占用较小的系统状态分区。

适配副本、原文件校验备份和状态保存在 root 私有目录 `/var/local/native-rss/home`。组件通过 bind mount 使用副本，原系统首页文件不改写。只有安装或移除自己的 Upstart 配置时临时将根分区改为可写，随后恢复原来的只读状态。启用成功后设备重启会自动加载；原文件哈希变化时跳过适配并保留原首页。

**升级、卸载或准备更新 Kindle 固件前，先选择“停用首页 RSS”，确认状态为未加载。** 再删除应用文件。直接删除程序目录会留下系统启动配置，无法执行正常恢复。停用后可保留私有备份用于排查；如需清除，先确认挂载已卸载和任务已停止，再删除 `/var/local/native-rss/home`。

已在本机 KPW3 固件 5.16.2.1.1 上验证真实 RSS 摘要、连续刷新、后台中断重连、阅读器按钮、阅读器退出恢复和停用恢复。当前仍为本地开发功能；其他设备、整机重启、固件升级和长时间休眠恢复尚未验证。
